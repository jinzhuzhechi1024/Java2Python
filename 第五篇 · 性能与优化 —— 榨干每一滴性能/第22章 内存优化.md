> 📖 本章你将学会：

> - 用memoryview实现零拷贝内存切片
> - 理解Python的引用计数与gc模块的分代回收

#### 第1节 对象内存开销：Java vs Python

理解内存优化的前提，是理解Python对象的内存结构为什么和Java不同。

**Java对象内存布局**：
```
+----------+----------+----------+----------+
| Mark Word| Klass ptr| 实例数据  | 对齐填充  |
| (8字节)  | (4字节压缩)| (字段值)  | (8字节对齐)|
+----------+----------+----------+----------+
```
Java对象头固定12-16字节（含Mark Word和Klass指针），实例数据紧跟其后。一个含两个int字段的Java对象约24字节[^java-obj-layout]。

**Python对象内存布局**：
```
+----------+----------+----------+----------+
|PyObject_HEAD| PyObject_HEAD| __dict__  | 实例数据  |
| (refcnt)  | (type ptr)   | (哈希表)  | (通过dict) |
| 8字节     | 8字节        | ~232字节  | —          |
+----------+----------+----------+----------+
```
Python每个对象有16字节的 `PyObject_HEAD`（8字节引用计数 + 8字节类型指针），但关键区别在于实例属性存储——Python用 `__dict__`（哈希表）存储实例属性，一个空dict本身就约232字节（CPython 3.12优化后约96字节）[^python-obj-layout]。

| 组件 | Java对象 | Python对象 |
|------|---------|-----------|
| 对象头 | 12-16字节 (Mark Word + Klass ptr) | 16字节 (refcnt + type ptr) |
| 实例数据 | 直接存储字段值 | 通过__dict__哈希表间接存储 |
| 对齐 | 8字节对齐填充 | 无额外对齐 |
| 100万个含2字段的User | ~24MB | ~56-80MB |

Python对象更大的根本原因：`__dict__` 是为了支持动态属性——你可以在运行时给任何对象添加新属性。Java的类字段在编译时就固定了，内存布局紧凑但丧失了灵活性。

> 💡 **第一性原理**：Python用内存换灵活性——`__dict__` 哈希表使得运行时动态加属性成为可能，代价是每个对象多占一个哈希表的内存。Java用编译期固定换取内存紧凑。这不是缺陷，是设计权衡。

#### 第2节 __slots__：省下30-60%内存的利器

`__slots__` 是Python内存优化的第一工具——它通过声明固定属性集，告诉解释器"这个类的属性不会动态变化，不需要 `__dict__`"[^slots-docs]。

```python
# 无__slots__——每个实例有__dict__，占内存大
class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

# 有__slots__——固定属性槽位，省去__dict__
class User:
    __slots__ = ('name', 'age')
    def __init__(self, name, age):
        self.name = name
        self.age = age
```

**__slots__的工作原理**：声明 `__slots__` 后，CPython为类生成一个C结构体，每个slot对应一个固定的描述符（descriptor）。属性访问通过描述符的 `__get__`/`__set__` 直接操作C结构体偏移量，而非哈希表查找[^slots-internals]。

实测对比（100万个User实例，CPython 3.12）：

| 指标 | 无__slots__ | 有__slots__ | 改善 |
|------|------------|------------|------|
| 单对象内存 | ~80字节 | ~48字节 | 节省40% |
| 100万对象总内存 | ~80MB | ~48MB | 节省40% |
| 属性访问耗时 | ~35ns | ~15ns | 快2.3x |
| 能否动态添加属性 | 是 | 否 | — |

> ⚠️ 不同CPython版本和平台的结果会略有差异。Python 3.12优化了对象布局，基础对象从208字节降至96字节[^py312-obj-size]，但 `__dict__` 仍然占额外内存。

**__slots__的代价**：
1. 不能动态添加未在 `__slots__` 中声明的属性
2. 类默认没有 `__weakref__`，无法被弱引用（除非显式加入 `__slots__ = ('name', 'age', '__weakref__')`）
3. 继承时子类也需声明 `__slots__`，否则子类实例又会有 `__dict__`

**何时用__slots__**：
- 百万级以上对象实例（内存收益明显）
- 属性集固定不变的数据类（如数据库记录、配置项）
- 高频属性访问场景（访问速度也提升）

**何时不用__slots__**：
- 对象数量少（<1万），内存差异可忽略
- 需要动态添加属性（如插件系统、ORM动态字段）
- 使用了某些依赖 `__dict__` 的库（如某些ORM框架）

#### 第3节 生成器：数据流的惰性求值

当处理大数据集时，列表会把所有数据加载到内存。生成器用惰性求值（lazy evaluation）逐个产出数据，内存占用从O(n)降为O(1)。

```python
import sys

# 列表——一次性加载1000万个数字到内存
numbers_list = [x ** 2 for x in range(10_000_000)]
print(sys.getsizeof(numbers_list))  # ~80MB

# 生成器——逐个产出，不占额外内存
numbers_gen = (x ** 2 for x in range(10_000_000))
print(sys.getsizeof(numbers_gen))   # ~200字节（仅生成器对象本身）
```

生成器表达式 `(x ** 2 for x in ...)` 和列表推导式 `[x ** 2 for x in ...]` 语法几乎相同，区别在于圆括号 vs 方括号——前者惰性求值，后者立即求值。

**生成器函数**——用 `yield` 逐个产出：

```python
def read_large_file(path):
    """逐行读取大文件，不一次性加载"""
    with open(path) as f:
        for line in f:
            yield line.strip()

# 使用——每行在需要时才读取
for line in read_large_file("huge_data.csv"):
    process(line)
```

**Java对比**：Java没有生成器语法糖，但可以用 `Stream` 实现类似效果。Java的 `Stream` 也是惰性求值——`Stream.iterate(0, x -> x+1).map(x -> x*x).limit(10_000_000)` 不会一次性生成所有数据。区别在于Python的生成器更轻量、更直觉。

#### 第4节 memoryview：零拷贝内存切片

`memoryview` 是Python中鲜为人知但强大的工具——它允许在不拷贝数据的前提下"查看"和切片内存缓冲区[^memoryview-docs]。

```python
# 切片一个大byte序列——普通方式会拷贝
data = b'x' * 10_000_000
chunk = data[1000:2000]  # 创建新的bytes对象，拷贝1000字节

# memoryview切片——零拷贝
mv = memoryview(data)
chunk = mv[1000:2000]  # 仅创建新的view对象，不拷贝数据
```

memoryview基于缓冲区协议（buffer protocol），NumPy数组、bytearray、bytes等都支持。对大型二进制数据（图像、音频、网络包）做切片操作时，memoryview可避免大量内存拷贝。

```python
# 处理NumPy数组时也适用
import numpy as np
arr = np.arange(1_000_000, dtype=np.float64)
mv = memoryview(arr)
# 切片创建view，不拷贝数据
sub_view = mv[100:200]
```

#### 第5节 引用计数与gc模块

Python的内存管理主要依赖引用计数（reference counting），辅以分代垃圾回收。

**引用计数**——每个PyObject有一个 `ob_refcnt` 字段，记录有多少引用指向该对象。引用增减时自动更新计数；计数归零时立即释放内存[^refcount-docs]。

```python
import sys

a = [1, 2, 3]       # refcnt = 1
b = a                # refcnt = 2
c = a                # refcnt = 3
print(sys.getrefcount(a))  # 输出4（函数参数临时引用也算1）

del b                # refcnt = 2
del c                # refcnt = 1
del a                # refcnt = 0 → 立即释放
```

引用计数的优势：**确定性释放**——对象不再被引用时立即回收，无需等待GC周期。这意味着Python不需要Java那样的Full GC停顿。

**引用计数的弱点：循环引用**：

```python
# 循环引用——引用计数无法回收
a = []
b = [a]
a.append(b)  # a引用b，b引用a → refcnt永远≥1
del a, b     # 外部引用消失，但内部循环引用使refcnt仍为1
```

`gc` 模块负责处理循环引用——它定期扫描对象图，检测并回收循环引用组[^gc-module]。gc模块使用分代策略（generation 0/1/2），新对象在gen0，经历GC存活后晋升到gen1、gen2，越老的代扫描频率越低。

```python
import gc

# 手动触发GC
gc.collect()

# 查看各代对象数量
print(gc.get_count())  # (gen0_count, gen1_count, gen2_count)

# 禁用/启用GC（某些场景如CPython启动时）
gc.disable()
gc.enable()
```

**Java对比**：

| 维度 | Python (引用计数+分代GC) | Java (分代GC) |
|------|------------------------|--------------|
| 主要回收机制 | 引用计数（即时） | 分代GC（周期性） |
| 循环引用处理 | gc模块分代扫描 | GC根可达性分析 |
| 释放时机 | 引用归零立即释放 | GC周期时批量回收 |
| 停顿问题 | 无Full GC停顿 | Full GC可能停顿数百ms |
| 内存碎片 | 低（即时释放） | 高（需要压缩） |
| 适合场景 | 通用 | 大堆+高吞吐 |

> 💡 **Java老兵关键认知**：Python不用像Java那样调优堆大小和GC策略。引用计数使对象释放即时且可预测——这是Python不需要JVM调优的原因。但引用计数每次赋值都有原子操作开销，这对多线程性能有影响（也是GIL存在的原因之一）。

#### 第6节 实战：大数据量对象的内存优化策略

**策略1：__slots__ + 数据类**

```python
from dataclasses import dataclass

@dataclass
class User:
    __slots__ = ('id', 'name', 'age', 'salary')
    id: int
    name: str
    age: int
    salary: float
```

**策略2：用NumPy结构化数组替代对象列表**

```python
import numpy as np

# 100万个User用对象列表——~80MB
users_list = [User(i, f"user_{i}", 30, 50000.0) for i in range(1_000_000)]

# 100万个User用NumPy结构化数组——~24MB（3.3x节省）
dtype = np.dtype([
    ('id', np.int32),
    ('name', 'U10'),    # 10字符Unicode
    ('age', np.int8),
    ('salary', np.float64)
])
users_arr = np.empty(1_000_000, dtype=dtype)
users_arr['id'] = np.arange(1_000_000)
users_arr['age'] = 30
users_arr['salary'] = 50000.0
```

**策略3：用生成器管道处理大数据流**

```python
def parse_csv_stream(path):
    with open(path) as f:
        header = next(f)  # 跳过表头
        for line in f:
            fields = line.strip().split(',')
            yield {
                'id': int(fields[0]),
                'name': fields[1],
                'salary': float(fields[3])
            }

# 管道式处理——内存占用恒定
for record in parse_csv_stream("10GB_data.csv"):
    if record['salary'] > 100000:
        save_to_db(record)
```

#### 本章小结

Python内存优化的核心策略：

用 `__slots__` 固定属性集，省去 `__dict__`，节省30-60%内存并加速属性访问2倍。适用百万级对象场景。

用生成器替代列表，将大数据流的内存占用从O(n)降为O(1)。适合文件读取、数据管道等流式处理。

用 `memoryview` 做零拷贝切片，避免大buffer的拷贝开销。适合二进制数据处理。

用NumPy结构化数组替代对象列表，在数值数据密集场景下可节省3-4倍内存。

理解引用计数+分代GC的机制，明白Python不需要像Java那样做JVM调优——引用计数的即时释放特性使Python没有Full GC停顿问题。

> 💡 **Java老兵记住**：Python的内存模型和Java本质不同。Java优化GC停顿和堆大小；Python优化对象大小和属性存储。不要把Java的对象池、GC调优套路搬到Python——Python的引用计数不需要这些。Python的内存优化方向是减少对象大小（__slots__）和减少对象数量（生成器/NumPy）。
